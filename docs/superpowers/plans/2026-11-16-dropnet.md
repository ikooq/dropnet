# Dropnet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn scattered (synthetic) Kazakh fraud complaints into connected campaigns in a Relate graph, with evidence paths, case files, a web UI and an MCP investigator — runnable with no API key.

**Architecture:** A deterministic Python pipeline (generate → extract → embed → load → link) writes a committed single-file Relate snapshot `data/dropnet.rl`. One shared query layer (`dropnet/tools.py`) serves the CLI, the FastAPI web app (which writes only to a live copy), the Python MCP server and the optional LLM agent.

**Tech Stack:** Python ≥3.10 (dev on 3.14), relate-db 1.0.1, FastAPI + uvicorn, sigma.js + graphology (CDN, pinned), official `mcp` Python SDK, pytest. Optional: pydantic-ai (Ask panel), sentence-transformers.

**Spec:** `docs/superpowers/specs/2026-11-16-dropnet-design.md`

## Global Constraints

- Python **3.10+**; must run on Windows, macOS, Linux. Open all text files with `encoding="utf-8"`.
- Relate mode **single file**: snapshot `data/dropnet.rl` (committed, written only by `build`); live copy `data/live/dropnet.rl` (gitignored).
- **No API key needed** for build, serve, ingest, investigate, eval, MCP. LLM paths only when `ANTHROPIC_API_KEY` is set.
- Judge path: `pip install -e .` then `python -m dropnet serve` → `http://localhost:8000`.
- Synthetic-data safety: phones only `+7 799 0xx xx xx`; cards only BIN `400000` shown masked `4000 00** **** NNNN`; IBANs start `KZ00`; domains end `.example` or `.test`; every node `synthetic: true`; UI and README say "Synthetic data".
- Complaint text in Russian; UI, README, CLI output, video in English.
- Campaign IDs are `CAMP-` + numeric part of the earliest complaint id in the campaign (`CAMP-0007`).
- Tactic codes exactly: `BANK_SECURITY, SAFE_ACCOUNT, LOAN_STATUS_SMS, MARKETPLACE_PREPAY, POLICE_THREAT, INVESTMENT, ATM_DROP_HELP`.
- Default dataset: seed 1, ~250 complaints, 6–8 campaigns, ~25 % noise, Jan–Jun 2026, 17 regions. Eval: thresholds tuned on seed 1; reported on seeds 2–5 and `--hard`.
- GitHub topics `relate`, `relate-neo4j-hackathon`. Deadline: submit by 2026-12-09.

## Review Focus

1. Phone/card numbers written in many shapes (`8 701…`, `+7(701)…`, `87010…`, spaced card digits) must resolve to one node — pinned in Task 3.
2. A pasted complaint with no extractable entity (or empty/very long text) must ingest as `unlinked` without crashing — pinned in Task 10.
3. A legitimate hub (marketplace support number in many unrelated complaints) must not merge campaigns — pinned in Task 6.
4. MCP and web UI running together on Windows must not hit the single-writer lock — pinned in Task 12.
5. `read_cypher` must refuse writes (`CREATE`, `MERGE`, `DELETE`, `SET`, `CALL db.*` writes) whatever the casing — pinned in Task 8.

### Task 5: Load dataset into Relate

**Files:** `dropnet/load.py`, `tests/test_load.py`.
**Consumes:** Tasks 1–4. **Produces:** `load.load_dataset(conn, ds: Dataset, extractions: list[Extraction]) -> dict[str, int]` (counts per label). Creates node/rel types exactly as spec §5 (Complaint, Phone, Card, Account, Url, Domain, Tactic, Region, Bank, Extraction; CONTACTED_BY, PAID_TO, FORWARDED_TO, VISITED, ON_DOMAIN, USED_TACTIC, FILED_IN, ISSUED_BY, FROM, FOUND). Uses `MERGE` on keys; batch with `UNWIND $rows`. Paid-to target = the card/IBAN extraction in a complaint whose context contains a transfer verb (перевел/отправил/оплатил); others → `MENTIONS` is NOT created (keep model small).

- [ ] Tests on a 10-complaint mini dataset: same phone in 2 formats → 1 `Phone`; every `Extraction` has `FROM` and `FOUND`; every Complaint has `script_vec` of dim 256; `synthetic = true` on all nodes. FAIL → implement → PASS → commit.

### Task 6: Linking and campaigns

**Files:** `dropnet/link.py`, `tests/test_link.py`.
**Produces:**
- `link.add_similarity(conn, k: int = 5, threshold: float) -> int` (writes `SIMILAR_SCRIPT {score}` using `db.index.vector.queryNodes`)
- `link.find_hubs(conn, min_tactics: int = 3, min_regions: int = 4) -> set[str]` (entity keys; sets `hub = true`)
- `link.strong_pairs(conn, max_hops: int = 3) -> list[tuple[str, str, str]]` (a, b, via-entity) via shared Phone/Domain/payee reachable over `FORWARDED_TO*0..max_hops`, excluding hubs
- `link.build_campaigns(conn, use_vectors=True, use_forwarding=True, use_hub_filter=True) -> list[Campaign]` — union-find over strong pairs; then attach weak (`SIMILAR_SCRIPT` ≥ threshold AND same tactic) when a complaint has ≥2 weak links into the same component, or form script-only components of size ≥3; writes `Campaign` + `PART_OF`, stable ids, `size, damage_kzt, regions, first_seen, last_seen, confidence` (= strong-edge share), sets `Card.role_hint` (`mule` ≥2 victim payers; `cashout` = sink of FORWARDED_TO chain).
- `models.Campaign(id, member_ids: list[str], confidence: float, ...)`

- [ ] Tests (mini fixtures): two complaints sharing card → same campaign; hub phone shared by 6 unrelated complaints → not merged; chain A→X→Y←B (depth 2) → merged; script-only trio → campaign; id equals earliest member (`CMP-0004` → `CAMP-0004`); re-running gives identical ids. FAIL → implement → PASS → commit.
