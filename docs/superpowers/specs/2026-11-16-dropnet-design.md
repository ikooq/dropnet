# Dropnet — дизайн

> Рабочее название: **Dropnet**. Подзаголовок для Devpost: *«Scattered fraud complaints → one connected case»*.
> Хакатон: Relate by Neo4j, приём работ до **11 декабря 2026, 18:00 PST** (12 декабря, 07:00 GMT+5).
> Статус: черновик на утверждение.

## 1. Зачем

В Казахстане интернет- и телефонное мошенничество — **57 % всех случаев мошенничества**
(13,1 тыс. случаев за январь–июль 2026). Главные схемы: «служба безопасности банка»,
«безопасный счёт», фишинговые SMS про «статус займа», предоплата на маркетплейсе,
угрозы «от полиции», дропы у банкоматов.

Боль: **заявления жертв лежат по отдельности**. Бабушка в Павлодаре, студент в Алматы
и предприниматель в Астане пишут заявления в разные отделы. Никто не видит,
что деньги всех троих ушли на одну и ту же карту-дроп, звонили им номера из одного пула,
а сценарий разговора — слово в слово. Связь существует только **в связях**,
а не в отдельной записи. Ровно тема хакатона: *Context, Connected*.

**Пользователь:** аналитик антифрод-центра (банк / регулятор) или следователь.
Момент использования: пришло новое заявление → «это часть чего-то большего?»
и «соберите мне дело по этой сети».

**Успех для нас** = призовое место. Это значит по критериям:
| Критерий | Баллы | Чем закрываем |
|---|---|---|
| Relate и связанный контекст | 30 | Граф — ядро: связывание, пути-доказательства, гибрид вектор+граф, MCP, один файл базы в репо |
| Функциональность | 25 | Полный сценарий работает end-to-end; есть метрика качества против эталона |
| Полезность | 20 | Реальная статистика КЗ, понятный пользователь, «дело за 30 секунд» |
| Документация | 15 | README по шаблону хакатона; запуск двумя командами без API-ключа |
| Креативность | 10 | Связывание *заявлений людей*, а не стандартные «кольца по транзакциям» |

## 2. Цели, не-цели, анти-цели

**Цели**
1. Загрузить заявления (свободный русский текст + немного структурных полей) в граф Relate.
2. Извлечь сущности: номера телефонов, карты, IBAN, ссылки/домены, суммы, тактики мошенников.
3. Связать заявления через общие сущности и похожие сценарии; выделить **кампании**.
4. Для любой связи показать **путь-доказательство** и **цитату из исходного текста**.
5. По кампании собрать **дело** (Markdown/HTML): масштаб, регионы, ущерб, дропы, пути, цитаты.
6. Дать ИИ-агенту (Claude Code и любому MCP-хосту) расследовать граф через MCP Relate.
7. Веб-интерфейс: входящие заявления, граф кампании, «новое заявление → мгновенная привязка».

**Не-цели** (не делаем)
- Реальные данные, интеграции с банками/операторами/полицией.
- Обучение ML-классификаторов, real-time стриминг.
- Многопользовательский режим, авторизация, продакшен-безопасность.
- Казахский язык интерфейса (возможен как бонус, не в плане).

**Анти-цели** (провал, даже если работает)
- Проект **не запускается без API-ключа** или без вопросов к нам.
- Синтетические данные выдаются за реальные, или в них попадают реальные номера/карты людей.
- Граф — «для галочки»: то же самое можно сделать одним SQL-джойном.
- Демо требует больше двух команд для первого результата.

## 3. Ограничения

- Python **3.10+** (у автора 3.14; 3.13 на машине сломан), Windows / macOS / Linux.
- `relate-db` 1.0.1 (Python, PyPI). CLI `relate` 1.0.1 нужен **только** для MCP-сервера.
- Режим Relate: **single file** — `data/dropnet.rl` закоммичен в репозиторий.
  Почему: судья видит и открывает один файл; переносимо; переживает перезапуск.
- Работа **без ключа**: всё ключевое детерминировано и офлайн. LLM — опциональное улучшение.
- Встраивания (embeddings) без скачивания моделей: хэшированные символьные n-граммы
  (см. §6.3). Опционально — мультиязычная модель, если установлена.
- Одна пишущая сессия на базу, и read-only открытие невозможно, пока есть писатель
  (ограничение Relate) → закоммиченная база `data/dropnet.rl` — **неизменяемый снимок**;
  живые изменения идут в рабочую копию (см. §13).
- Срок ≈ 25 дней, один разработчик + Claude Code.

## 4. Подходы (рассмотрены, выбран №2)

1. **Всё в браузере (relate-wasm).** Плюс: открыл ссылку — работает. Минус: нет агента/MCP
   и Python-экосистемы; агентная часть слабая. Отклонён как основа (возможен позже как бонус).
2. **Python-ядро + веб-интерфейс + MCP.** ⭐ *Выбран пользователем.*
   `relate-db` для конвейера и агента, FastAPI + статичный фронтенд с sigma.js,
   `relate serve --mcp stdio --read-only` для внешних агентов. Закрывает все критерии.
3. **Только CLI + skill для Claude Code.** Быстрее всего, но слабое видео и непонятно
   для аналитика. Отклонён.

Пробный запуск (16.11, Windows, Python 3.14, relate 1.0.1) подтвердил: single-file база,
многошаговые запросы, `shortestPath`, векторный индекс + `db.index.vector.queryNodes`,
гибрид вектор+граф, кириллица, MCP через stdio (`read_cypher`, `get_schema`). HTTP-MCP требует
токен — не используем.

## 5. Модель графа

### Узлы
| Метка | Ключ | Свойства |
|---|---|---|
| `Complaint` | `id` (`CMP-0001`) | `filed_at` (date), `region`, `channel` (call/sms/marketplace/messenger), `amount_kzt`, `text` (рус.), `text_en` (краткий перевод для UI), `victim_age_band`, `script_vec` (вектор), `synthetic: true` |
| `Phone` | `e164` | `display`, `first_seen`, `last_seen` |
| `Card` | `pan_masked` (`4000 00** **** 1234`) | `bank`, `role_hint` (victim/mule/cashout — вычисляется) |
| `Account` | `iban` | `bank` |
| `Url` | `url` | `domain` |
| `Domain` | `name` | `registered_at` (синт.) |
| `Tactic` | `code` (`BANK_SECURITY`, `SAFE_ACCOUNT`, `LOAN_STATUS_SMS`, `MARKETPLACE_PREPAY`, `POLICE_THREAT`, `INVESTMENT`, `ATM_DROP_HELP`) | `label_ru`, `label_en` |
| `Region` | `name` | — |
| `Bank` | `name` | — |
| `Campaign` | `id` (`CAMP-01`) | `size`, `damage_kzt`, `regions`, `first_seen`, `last_seen`, `confidence`, `summary` |
| `Extraction` | `id` | `complaint_id`, `kind`, `value`, `span_start`, `span_end`, `quote`, `extractor` (`rules`/`llm`) |

### Связи
| Связь | Смысл |
|---|---|
| `(Complaint)-[:CONTACTED_BY {channel}]->(Phone)` | с какого номера звонили/писали |
| `(Complaint)-[:PAID_TO {amount_kzt, at}]->(Card\|Account)` | куда жертва перевела деньги |
| `(Card)-[:FORWARDED_TO {amount_kzt, at}]->(Card\|Account)` | движение денег дальше (синтетическая выписка банка) |
| `(Complaint)-[:VISITED]->(Url)-[:ON_DOMAIN]->(Domain)` | фишинговые ссылки |
| `(Complaint)-[:USED_TACTIC]->(Tactic)` | сценарий |
| `(Complaint)-[:FILED_IN]->(Region)`, `(Card)-[:ISSUED_BY]->(Bank)` | контекст |
| `(Complaint)-[:SIMILAR_SCRIPT {score}]->(Complaint)` | похожий текст разговора (порог, top-k) |
| `(Complaint)-[:PART_OF]->(Campaign)` | результат связывания |
| `(Extraction)-[:FROM]->(Complaint)`, `(Extraction)-[:FOUND]->(сущность)` | **происхождение**: каждая связь сводится к цитате |

Ключевая идея: любой вывод («эти 12 заявлений — одна кампания») объясняется **путём**
`Complaint → сущность → … → Complaint` и **цитатами** через `Extraction`.

## 6. Компоненты

### 6.1 Генератор синтетических данных — `dropnet/synth/`
- Детерминированный (`seed`), создаёт ~**250 заявлений** за 6 месяцев 2026, 17 регионов.
- **6–8 скрытых кампаний** (эталон) с разной «связностью»: общая карта-дроп; пул номеров;
  общий фишинговый домен; цепочки `FORWARDED_TO` глубиной 2–4; одна кампания связана
  *только* похожим сценарием (проверка вектора); одна — через двух общих дропов.
- ~25 % «шумовых» одиночных заявлений; ложные совпадения (один популярный маркетплейс-номер
  поддержки, который не мошенник) — чтобы связывание не было тривиальным.
- Тексты на русском из шаблонов по реальным схемам 2026 + вариации (перефразы, опечатки,
  разные форматы номеров/карт: `8 701…`, `+7(701)…`, `4000 00** **** 1234`).
- **Безопасность данных:** телефоны только из явно фиктивного диапазона
  (`+7 799 0xx xx xx`, помечен в README как вымышленный); карты — тестовые BIN `4000 00`
  и маска; IBAN с префиксом `KZ00` (невалидная контрольная сумма); домены `.example`/`.test`
  или с суффиксом `-demo`. Все узлы `synthetic: true`. В UI и README — пометка «Synthetic data».
- Выход: `data/raw/complaints.jsonl`, `data/raw/bank_transfers.jsonl`,
  `data/ground_truth.json` (кампания → id заявлений).

### 6.2 Извлечение — `dropnet/extract/`
- **Правила (по умолчанию, офлайн):** регулярки KZ-номеров (с нормализацией в E.164),
  карт (маскированных и полных → маска), IBAN `KZ..`, URL/доменов, сумм в тенге
  («50 тыс.», «50 000 тг», «₸»), словарь тактик (стеммы: «безопасн», «служба безопасности»,
  «статус займа», «предоплат», «следовател», «помогите перевести у банкомата»).
  Каждое попадание → `Extraction` со смещением и цитатой.
- **LLM (опционально, `ANTHROPIC_API_KEY`):** Claude через `pydantic-ai` с типизированной
  схемой вывода — дополняет то, что правила пропустили (тактика по смыслу, сумма словами).
  Результаты **кэшируются** в `data/cache/llm_extractions.jsonl` и коммитятся →
  судья без ключа получает тот же граф.
- Модель по умолчанию: последняя Claude Sonnet (решение строителя по актуальному ID).

### 6.3 Векторы сценариев — `dropnet/embed/`
- По умолчанию: **хэшированные символьные 3–5-граммы** нормализованного текста
  → 256-мерный вектор, L2-нормализация. Чистый Python, без загрузок, хорошо ловит
  перефразы русского текста.
- Опционально: `sentence-transformers` (мультиязычная модель), если установлен extra `[ml]`.
- Векторный индекс Relate `complaint_script` (cosine). `SIMILAR_SCRIPT` — top-5 соседей
  с порогом (подбирается на эталоне).

### 6.4 Связывание и кампании — `dropnet/link/`
- Нормализация и слияние сущностей (один номер в разных форматах → один `Phone`).
- **Сильные связи:** общий `Phone`, общая карта/счёт получателя (включая достижимость
  по `FORWARDED_TO` до 3 шагов), общий `Domain`.
- **Слабые связи:** `SIMILAR_SCRIPT` выше порога **и** совпадение тактики.
- Кампании = компоненты связности графа заявлений по сильным связям, затем
  присоединение по слабым при достаточной поддержке. Алгоритм — union-find в Python
  поверх результатов Cypher-запросов; результат пишется обратно в Relate
  (`Campaign`, `PART_OF`).
- **Фильтр хабов:** сущность, связанная с аномально многими несвязанными тактиками/регионами
  (например, номер поддержки маркетплейса), понижается в весе и помечается — защита от ложных склеек.
- `confidence` кампании — по доле сильных связей.
- Роли карт: `mule` (входящие от ≥2 жертв), `cashout` (лист цепочки `FORWARDED_TO`).

### 6.5 Дело (case file) — `dropnet/report/`
- По `CAMP-xx`: сводка (заявлений, регионов, ущерб, период), тактики, топ дропов по входящим,
  **3–5 путей-доказательств** (из `shortestPath` между заявлениями), цитаты из `Extraction`,
  карта регионов (таблица), рекомендации («заблокировать карты …», «запросить данные по номерам …»).
- Форматы: Markdown (для репо и агента) и HTML (для UI/печати).

### 6.6 Агент-расследователь — `dropnet/agent/`
- `pydantic-ai`, модель Claude. Инструменты: `get_schema`, `read_cypher` (только чтение,
  через Python-соединение `read_only=True`), а также узкие: `find_campaign(complaint_id)`,
  `explain_link(a, b)`, `top_mules(campaign_id)`, `similar_scripts(text)`, `build_case(campaign_id)`.
- Каждый ответ агента обязан ссылаться на id узлов и путь — иначе ответ отклоняется (валидация вывода).
- Без ключа: команда `dropnet investigate CMP-0123` выполняет тот же сценарий детерминированно
  (без LLM-формулировок) и печатает дело.

### 6.7 MCP для внешних агентов
- **Основной путь (без доп. установки):** `.mcp.json` в корне репо запускает
  `python -m dropnet mcp` — MCP-сервер на Python (официальный `mcp` SDK, stdio) поверх
  `relate-db`. Если запущен `dropnet serve`, MCP-процесс не открывает файл сам, а ходит
  в веб-сервер (`/api/cypher`, только чтение) → видит живые изменения; иначе открывает
  снимок `data/dropnet.rl` read-only. Инструменты: `get_schema`, `read_cypher`
  + узкие (`find_campaign`, `explain_link`, `top_mules`, `similar_scripts`, `build_case`).
- **Родной путь Relate (для судей, у кого есть CLI):** второй сервер в `.mcp.json` —
  `relate serve --database data/dropnet.rl --mcp stdio --read-only` (по снимку).
  В README — оба, с пометкой, что второй требует установки CLI.
- Skill для Claude Code `.claude/skills/dropnet-investigator/SKILL.md`: схема графа,
  готовые Cypher-шаблоны («найти кампанию», «путь между заявлениями», «дропы кампании»),
  правило «всегда приводи путь и цитату».
- В README — пример: открыть репо в Claude Code и спросить «Кто стоит за CMP-0042?».

### 6.8 Веб-интерфейс — `dropnet/web/` + `web/static/`
- FastAPI (одно пишущее соединение Relate на процесс) + статичный HTML/JS, **sigma.js** с CDN.
- Экраны:
  1. **Inbox** — список заявлений (регион, тактика, сумма, кампания-бейдж).
  2. **New complaint** — вставить текст → извлечение → запись в граф → *мгновенно*:
     «Связано с CAMP-03 через карту `…1234` (её получали ещё 11 жертв)» + путь.
  3. **Campaign graph** — граф кампании; клик по связи показывает цитату-доказательство.
  4. **Case file** — дело в HTML, кнопка «Скачать Markdown».
- Язык UI — английский; тексты заявлений — русские с краткой английской подписью (`text_en`).

### 6.9 CLI — `dropnet` (через `python -m dropnet`)
- `build` — генерация → извлечение → векторы → связывание → запись `data/dropnet.rl`.
- `serve` — веб-интерфейс на `localhost:8000`.
- `ingest "<текст>"` — добавить заявление и показать привязку.
- `investigate <CMP-id>` / `case <CAMP-id>` — дело в консоль/файл.
- `eval` — качество связывания против эталона.

### 6.10 Оценка качества — `dropnet/eval/`
- Метрики: пары заявлений «в одной кампании» — precision / recall / F1; чистота кампаний.
- Цель: **F1 ≥ 0.9** на синтетике; отдельно показать вклад векторов (с/без `SIMILAR_SCRIPT`).
- Результат — таблица в README (убедительно для критерия «функциональность»).

## 13. Решения после проверки строителем

1. **Снимок и рабочая копия.** `data/dropnet.rl` (в git) пишет только `build`.
   `serve` при старте копирует снимок в `data/live/dropnet.rl` (в `.gitignore`) и пишет
   туда; `serve --reset` начинает с чистого снимка. Веб-сервер — единственный писатель
   живой копии; MCP ходит к нему по HTTP (§6.7). Так демо-шаги 2 и 4 работают одновременно,
   а `build` и `eval` остаются детерминированными.
2. **Новые заявления** живут только в рабочей копии и не меняют снимок и метрики.
3. **Инкрементальная привязка** (без пересчёта всего графа):
   - связь с одной кампанией → `PART_OF` к ней, пересчёт её сводки;
   - связь с двумя и более → привязка к самой сильной + флаг **«мост»** и предложение
     объединить (автоматически не объединяем, ID не меняются);
   - нет связей → `status: 'unlinked'`, показываем топ похожих сценариев как кандидатов.
   - **ID кампаний стабильны**: `CAMP-` + id самого раннего заявления кампании
     (`CAMP-0007`) — не зависят от порядка обхода union-find.
4. **Агент на pydantic-ai урезан:** не отдельная неделя, а панель «Ask» в UI (≈2 дня),
   работает только с ключом и использует **те же функции-инструменты**, что и MCP.
   Главный агентный сценарий для судей — Claude Code через MCP + skill.
5. **«Бюджет»** в §9 — это лимит Claude Code у автора, не платный API. Есть ли API-ключ
   для разовой предгенерации LLM-кэша — вопрос к пользователю (см. §14).
   Без ключа: `text_en` берётся из англ. версии шаблона генератора; для живых
   заявлений без ключа — показываем извлечённые факты на английском
   («Tactic: bank security · Paid to card …1234 · 120 000 KZT») вместо перевода.
6. **Честная оценка:** пороги подбираются на seed 1 (dev); в README — метрики на
   seeds 2–5 (test) **и** на «жёстком» варианте генератора (больше перефраз, опечаток,
   смешанных форматов, кампаний только по сценарию). Показываем и абляцию
   (без векторов / без `FORWARDED_TO` / без фильтра хабов).
7. **Установка:** две команды для UI **и** MCP (Python MCP-сервер ставится вместе с пакетом).
   Relate CLI — опционально, только для «родного» MCP-пути.
