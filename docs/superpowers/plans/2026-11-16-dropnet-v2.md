# Dropnet v2 Implementation Plan — real FTC data + Relate depth

> Executed inline (superpowers:executing-plans), TDD per task. Spec: design §15.

**Goal:** Real, large, public complaint data (FTC Do Not Call reports) in Relate, campaigns that per-number blocklists
miss (neighbor spoofing, number pools), an honest temporal hold-out against a blocklist baseline, what-if
transactions, per-case files, a no-install browser demo on Relate WASM, an agent hook, and a strong submission.

## Global constraints
- Source: FTC DNC complaint CSVs (`https://www.ftc.gov/sites/default/files/DNC_Complaint_Numbers_YYYY-MM-DD.csv`),
  US government public data. Raw files stored gzipped in `data/ftc/raw/`. Parse with the `csv` module (quoted commas).
- Store: `data/ftc.rl`, committed, must stay ≤ 95 MB; if larger, use the most recent N days and say so.
- Never label a number "fraudster": UI and docs say "reported number"; spoofed numbers may belong to innocent people.
- Everything still runs with no API key; v1 (Russian free-text module) keeps working and its tests stay green.

## Tasks
1. **Fetch + parse** — `dropnet/ftc/fetch.py` (`fetch(days)` → gz files; idempotent), `dropnet/ftc/parse.py`
   (`parse_row(dict) -> Report | None`, `read_reports(paths) -> Iterator[Report]`). Report fields: `id`, `number`
   (10 digits), `npa`, `nxx`, `created`, `violation`, `city`, `state`, `victim_npa`, `subject` (normalised code +
   label), `robocall` (bool|None), `neighbor` (number npa == victim npa). Tests: quoted subjects, bad numbers
   rejected, robocall flags, neighbor flag.
2. **Load** — `dropnet/ftc/load.py`: `(:Report)-[:FROM_NUMBER]->(:Number)-[:IN_BLOCK]->(:Block {npa_nxx})-[:IN_AREA]->(:AreaCode)`,
   `(:Report)-[:ABOUT]->(:Subject)`, `-[:VICTIM_IN]->(:State)`, `-[:VICTIM_AREA]->(:AreaCode)`, `-[:ON_DAY]->(:Day)`.
   Batched UNWIND/MERGE. Measure size/time on 1 day before loading all.
3. **Campaigns** — `dropnet/ftc/campaigns.py`: (a) *number pools*: numbers in one Block with the same Subject within
   a 3-day window, ≥ 3 numbers and ≥ 5 reports; (b) *spoofing signatures*: (Subject, robocall, neighbor=true)
   per day with many one-off numbers; (c) *repeat numbers* (high-volume single numbers). Write `(:FtcCampaign)`.
4. **Hold-out evaluation** — `dropnet/ftc/evaluate.py`: train = first 18 days, test = rest. Baseline blocklist:
   numbers with ≥ k reports in train. Dropnet rules: blocks of number pools + numbers. Report coverage of test
   reports at equal rule budgets, and collateral (numbers covered by block rules that were never reported).
   CLI `python -m dropnet ftc-eval`. Write `docs/ftc-eval.md`.
5. **What-if + case file** — `whatif(conn, rules)` runs inside an explicit Relate transaction (autocommit off):
   create `:Rule` nodes, count reports matched, roll back; test proves nothing persisted.
   `export_case(conn, campaign_id, path)` writes one `.rl` file with the campaign subgraph.
6. **Web + MCP** — "Real data" tab: campaign list, neighbor-spoofing map by state, what-if slider; MCP tools
   `ftc_campaigns`, `assess_number`, `whatif_block`.
7. **Browser demo** — `site/` static page with `@relate/relate-wasm` loading `site/data/sample.json`
   (recent days, capped size) into an in-browser Relate; campaign graph, Cypher console, what-if. GitHub Pages ready.
8. **Agent hook** — `.claude/hooks/number_guard.py` (UserPromptSubmit/PreToolUse) + `assess_number`: when a phone
   number appears, inject evidence and the spoofing caution.
9. **Submission** — README v2 (real data first), Devpost text, screenshots list, demo script v2.
